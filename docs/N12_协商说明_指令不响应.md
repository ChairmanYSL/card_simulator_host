## 1. 需求背景

构造“终端对某条 APDU 指令得不到任何应答”的异常用例。最典型场景：
**卡片对 GPO（GET PROCESSING OPTIONS）不响应** → 终端等不到响应 → 超时 /
不再发起交易。这是**静默（无响应 APDU）**，与已有 `ppseMode:disabled`
（回错误 SW 6A82）语义不同，需要新增档案字段表达。

## 2. 协议变更（host 已实现，随 card_config.profile 下发）

`CardProfile` 新增可选字段（camelCase）：

```jsonc
"noResponseCommands": [
  "GPO",                                   // 简写：每次收到 GPO 都不响应
  { "command": "READ_RECORD", "times": 1 } // 仅前 1 次静默，之后正常应答
]
```

| 形态 | 语义 |
|---|---|
| `"<COMMAND>"` | 该指令**每次出现都静默**（缺省形态） |
| `{"command":"<COMMAND>","times":N}` | 仅**前 N 次**静默，第 N+1 次起正常响应（N≥1） |

字段缺省 / `[]` = 全部指令正常响应。

## 3. 命令名注册表（第一期）

| 名称（大写） | 对应指令 |
|---|---|
| `PPSE` | SELECT PPSE（2PAY.SYS.DDF01） |
| `SELECT` | SELECT AID（应用选择） |
| `GPO` | GET PROCESSING OPTIONS |
| `READ_RECORD` | READ RECORD |
| `GET_DATA` | GET DATA |
| `GENERATE_AC` | GENERATE AC |
| `CCC`（别名 `MSD_AC`） | MSD AC / COMPUTE CRYPTOGRAPHIC CHECKSUM（`80 2A 8E 80`，仅 MSD 模式；2026-10-10 协商项 B 定稿） |
| `VERIFY` | VERIFY（PIN） |

host 侧：注册表之外的名称 → 加载 warning（放行，不阻断）；重复指令 → warning。

## 4. 请安卓侧确认并实现

1. **识别**：card_config.profile 收到 `noResponseCommands` 后，按命令名注册表
   匹配 APDU（建议同时兼容按 INS/命令类识别，注册表名→APDU 的映射由 app 侧
   实现并回写确认，见第 5 条）；
2. **静默语义**：命中指令时**不发送任何响应 APDU**（无数据、无 SW），保持
   NFC 场存活但不应答；`times:N` 计数按**单次模拟会话（start_emulation 起、
   stop_emulation 止）**累计，跨用例不延续；
3. **状态机**：静默不应改变 `ready/emulating` 状态上报；APDU trace（Phase A）
   仍可记录该指令为“已收到、无响应”（可选，便于排查）；
4. **边界**：与 `ppseMode:disabled`（回 SW）独立，可同时存在互不影响；
   与 `stop_emulation` 等 host 控制消息无关（静默只作用于终端侧 APDU 指令）。
