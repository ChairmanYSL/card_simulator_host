## 2. 对第 7 条两点待确认的 host 答复

**① GET_DATA / VERIFY 正常应答路径 —— 本期不纳入。**

第一期用例（含 UPI-CL-006/007 联调用例）只需要“静默本身”，不需要静默后恢复
正常数据应答；app 内核对这两条指令维持现状（回 6D00）即可。
后续若出现“GET_DATA 静默 N 次后正常返回数据（如 9F17 PIN Try Counter）”的
用例需求，host 将另立协商项（拟编号 N13），届时与 app 一并排期实现内核 handler。

**② 真机行为风险 —— host 知悉并接受。**

同意先按 `return null` 方案联调；真机 + 真实 POS 验证终端确实等待超时
（而不是收到异常字节/立即失败）。若实测个别 ROM 上终端未超时或行为异常，
双方再议备选方案（备选方向：内核级不发送响应帧 / 以其它方式保持场存活，
具体另行协商）。
