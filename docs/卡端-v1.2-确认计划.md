# 卡端 v1.2 确认计划（请卡端阅读后逐项回复）

> 日期：2026-09-14
> 目的：host 已完成 v1.2 的 P0+P1 改造（本地 mock 验证 26 场景 / 187 断言通过）。v1.2 是硬切换，卡端升级前需先逐项确认下列问题；卡端回复后，host 才发起 L5 真机联调。
> 使用方式：卡端对每项给出 CONFIRMED / CHANGE / BLOCKED 并在回复栏写明结论与依据；全部确认后再回复版本号/commit/APK。
> 关联：docs/v1.2-测试审核与修复计划.md、docs/test-report-v1.2/REPORT.md 第 9 节、docs/test-plan-v1.2.md 第 7.1 节。

---

## 0. 为什么需要这张确认表
- v1.2 拒绝小于 1.2 或缺失 protocol_version 的客户端；两端必须同窗口升级，混跑只会得到 protocol_mismatch。
- host 删除了 device_config、把 trace 开关移入 card_config、新增 session_abort，并改变了失败/断线语义。
- 测试报告 H2 发现：早期失败路径下卡端可能只收到 session_abort 而收不到 stop_emulation；host 会修（TS-5），但卡端也需明确 session_abort 即停止作为兜底。
- 卡端行为一旦确认，host 才能把卡端已就绪写入 L5 preflight。

## 1. 逐项确认清单

### K1 协议版本与硬切换
- 背景：host 仅接受 protocol_version 大于等于 1.2，缺失也拒绝；handshake_ack 回显 1.2。
- 需卡端确认：升级后握手带 protocol_version=1.2；确认升级窗口与可回退版本；确认 handshake 的 v 仍为 1。
- host 验收：host 日志出现 handshake ok: ... protocol=1.2。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K2 取消 device_config
- 背景：host 不再向任何端发送 config_push{config_type=device_config}。
- 需卡端确认：卡端不再等待 device_config；心跳/判死/ack 超时改用缺省（心跳 10s / warn 30s / ack 15s）；确认无其它依赖 device_config 的字段。
- host 验收：卡端在未收 device_config 时正常握手、心跳、跑用例。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K3 trace 开关改由 card_config 携带
- 背景：card_config 新增 trace_enabled: bool（host CLI --trace-enabled 控制）；trace 事件格式不变。
- 需卡端确认：从 card_config.trace_enabled 读取（缺省 false）；trace_enabled=true 时按现有 log{level=trace} 上报；是否保留旧 device_config 兼容分支。
- host 验收：--trace-enabled 下 trace/VISA-CL-001.jsonl 出现 4 行（2 对 APDU）。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K4 session_abort 语义与 ack
- 背景：host 到双方新增 session_abort，字段 run_id / brand / mode / case_id / attempt_id / reason / action；案例 FAIL、超时、断线、manual abort/stop、server_shutdown 时发出。
- 需卡端确认：1) 收到后必 ack；2) 将 session_abort 视同停止 HCE / 释放会话（即使已收到或未收到 stop_emulation）；3) 字段是否够用，是否需要额外错误码/原因枚举。
- host 验收：host 日志 session_abort broadcast；卡端日志出现被消费记录。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K5 stop_emulation ack
- 背景：host 等卡端 stop_emulation ack（3s best-effort）；正常/失败收尾都会发（TS-5 修复后覆盖 emulating 之后所有路径）。
- 需卡端确认：ack + status=stopped；保留 AID 注册与 profile 供下一 attempt；确认 stop_emulation 幂等。
- host 验收：卡端 ack；host 日志无 stop_emulation ack not received。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K6 坏帧容忍
- 背景：host 单连接累计 5 个 FrameDecodeError 才断连；每个坏帧跳过继续读。
- 需卡端确认：卡端同规则，单个坏帧不得拆链；累计 5 个才断开并重连。
- host 验收：L4_1 注入 5 坏帧，连接在第 5 个才断；卡端无异常崩溃。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________


### K7 status ready/emulating 时序
- 背景：host 在 start_emulation ack 后等待卡端 status{state=emulating}，预算 15s；status{state=ready} 仅日志。
- 需卡端确认：ready 的 detail 字段（profile_id / default_payment_app / registered_aids / ac_crypto）是否保留；emulating 的到达时限是否可满足；异常时应发 status{state=error, detail:{code,message}}（host 会置案例 ERROR）。
- host 验收：E2 超时路径可复现；正常路径卡端 ready -> emulating。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K8 app_version 上报与 preflight
- 背景：L5 preflight 要比对两端 app_version 与期望版本；/api/health 不返回协议版本，需看握手日志。
- 需卡端确认：升级后 app_version 的取值来源与格式（建议 BuildConfig.VERSION_NAME）；提供版本号、versionCode、commit、APK 大小。
- host 验收：/api/health 的 devices.android.app_version 与期望一致。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　版本=__________ commit=__________

### K9 card_config profile/keys 契约不变
- 背景：v1.2 卡端仍收完整 profile（不剔除非行为字段）+ 并列 keys；仅新增 trace_enabled，不再有 device_config。
- 需卡端确认：解析逻辑不变；profile.id 必须非空（host 已用 case_id 兜底）；network 未知值的兜底行为不变。
- host 验收：现有卡端用例（VISA-CL-001/002、UPI-CL-002）行为零变化。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K10 早期失败兜底（H2 双保险）
- 背景：host 将修 TS-5，确保卡端 emulating 后任何失败都补发 stop_emulation；但为防漏，卡端也应把 session_abort 视同停止。
- 需卡端确认：接受 stop_emulation + session_abort 双保险；session_abort 单独到达时也能停止 HCE。
- host 验收：L3 F_pos_not_connected 卡端既有 session_abort，TS-5 后还有 status=stopped。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K11 trace / 日志格式
- 背景：trace 事件 log{level=trace, message:{...}, case_id, attempt_id}；host 按 attempt 落盘 trace/<case>.jsonl。
- 需卡端确认：字段/编码与现版本一致；trace_enabled 关闭时不得上报（或仅本地日志）。
- host 验收：--trace-enabled 下 trace 落盘 4 行；关闭时 0 行。
- 卡端回复：CONFIRMED / CHANGE / BLOCKED　说明：__________

### K12 v1.2 回归红线
- 背景：round #15 基线 28/28（POS 1.0.13 + 卡端 1.0.31）；v1.2 不得改变卡端 APDU 行为。
- 需卡端确认：升级到 1.2 仅为通信层改造，APDU/内核行为零变化；确认回归范围（至少 VISA-CL-001/002、UPI-CL-002）。

## 3. 卡端确认通过后 host 的动作
1. host 完成 TS-1 至 TS-5 修复并重跑 L1-L4 全绿；
2. 两端都发出 [READY]，且 app_version 与 --expect-versions 一致；
3. host 日志确认 handshake ok: ... protocol=1.2；
4. 先跑红线案例（VISA-CL-001/002、UPI-CL-002），再跑全量 L5/L6。

## 4. host 对卡端的依赖与兜底

| 依赖 | host 侧兜底 | 若卡端不确认 |
|---|---|---|
| session_abort 即停止 HCE | TS-5 保证 emulating 后必发 stop_emulation | H2 维持 P1；L6 跨案例残留风险不解除，L5 不发起 |
| 换用 card_config.trace_enabled | host 已实现；关闭时不下发 true | trace 证据不可得，L5 可跑但 trace 验收项不可判 |
| 不再等 device_config | host 已删除该帧 | 卡端会卡在等待；L5 不发起 |
| 1.2 硬切换 | host 已实现 | 混跑必 protocol_mismatch，L5 无有效结论 |
