## 1. 逐项裁决说明

### 3.1 ready.registered_aids
- 裁决：选 c，保持 []。
- 理由：host 的 executor._on_android_status 只把 ready.detail 的 default_payment_app / ac_crypto / profile_id 用于日志，registered_aids 不是判据；emulating.registered_aids 才是真实注册结果。
- host 侧：增加一条日志记录 emulating.registered_aids（H-LOG，可选）；卡端零改动。
- 后续：若将来 host 需要 ready 阶段的计划列表，再单独提 K7-b。

### 3.2 session_abort 与 status{stopped}
- 裁决：选 b，仅 ack + 静默停止，不补 status 帧。
- 理由：host 只等 ack，不消费 status；v1.2 host TS-5 修复后，只要卡端已 emulating，收尾必发 stop_emulation 并已带 status{stopped}；避免冗余帧。
- 注意：卡端仍须保证 session_abort 单独到达时也停止 HCE（K10），只是不发 status。

### 3.3 坏帧定义与 L4_1 注入类型
- 确认：L4_1 注入的 5 个坏帧均为长度前缀合法、payload 非法 JSON。
- 统一口径：JSON 非法（长度合法）计入累计计数，跳过继续读，累计满 5 才断连；长度非法（声明长度大于 1 MiB）立即断开，不计入累计 5，落一条 frame_decode_error 日志；卡端当前每帧成功即 badFrames=0 改为不重置。
- host 侧现状一致：FrameDecodeError 累计跳过（connection.py:206-214），FrameTooLargeError 立即断（frame.py:51-52）。
- docs/test-plan-v1.2.md 的 L4_1 描述需补一句注入类型（TS-7）。

### 3.4 v1.2 基线
- 确认：v1.2 以 1.0.31 (vc33, commit 83589d5, 产物 ebaa811) 的 APDU 行为为基线，不含 N13。
- 卡端 v1.2 仅通信层改造：协议常量、trace 来源、session_abort、坏帧计数；不动 EMV 内核/AID 注册/N11/N12。
- N13（1.0.32/vc34, ea90149）保持不部署；如将来需要，按另行专项验证（无 -1304、VISA-CL-002 仍 declined）。
